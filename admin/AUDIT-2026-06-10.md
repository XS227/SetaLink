# Admin Dashboard Health-Check Audit — 2026-06-10

Production verdict first: **users were never affected.** Traffic is
flowing normally (1,723 authenticated connections accepted today on the
edge box alone). The scary dashboard warnings were false positives from
checks that probed the wrong port, the wrong machine, or ran without the
privileges they needed.

## Real issues found (true positives)

1. **Disk 90% full** on the edge box — surfaced by the new Service
   Health check. Fix: `journalctl --vacuum-size=200M && apt-get clean`,
   then consider logrotate tightening for `/var/log/xray/error.log` (1.9 MB/day).
2. **Bootstrap SNI is `www.cloudflare.com`**, while the validated
   Iran fix was `www.microsoft.com` SNI (see Iran investigation memory).
   The new iran-score flags this honestly (70/100, grade B). Decide
   whether to switch the bootstrap profile.
3. **12 UUID rejections today** for `3383c666-…f92` — a client (or
   probe) using a revoked/unknown UUID against the edge. Worth watching
   on the new Inbound Traffic panel; not user-impacting.

→ Protocol Health + Service Health → Live Usage + Transport Adoption →

→ Inbound Traffic (real counters) → Top SNI.

referrals, payments, quota). `action=service-health` replaces
