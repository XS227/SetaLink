# v0.9.34 — API domain fix + multi-node discovery (plan)

**Date:** 2026-06-14 · **Status:** source changes staged, **NOT built, NOT shipped, NO rollout.** Current users unaffected.

Scope is deliberately small and **low-risk**: fix the wrong API domain, enable multi-node discovery against a domain we own, and stop harmless failed network calls. **No VPN/Reality protocol changes, no bootstrap change, no auto-routing.**

---

## 1. Why (the bug being fixed)
The shipped binary hardcodes `API_BASE = https://api.setalink.net/v1` (`client.ts`). We do **not** own `setalink.net` (NS = Namecheap `registrar-servers.com`, not our `proisp.no`), so:
- every `/v1` call (`ServersAPI.list` on launch, `ServersAPI.getConfig` on connect) fails at DNS and falls back — multi-node has never worked;
- `admin.setalink.no` (no DNS record) is also dead — two diagnostics POSTs always fail.

Today's working path is unaffected and stays as-is: **`https://setalink.no/api.php`** (bootstrap/entitlement/messages) + `setalink.no/download/version.json`.

## 3. Multi-node behaviour (already safe in `public/v1.php`)
No client logic change needed — the store already falls back on any `/v1` failure. Server enforces:
- **Denmark/primary = default**, returned to everyone (read live from `bootstrap_*` settings).
- **Helsinki (`fi-hel`) = test-only**, returned **only** to devices in `node_allowlist`; `/config` is `403` otherwise.
- **No auto-routing** — testers must manually select Helsinki; everyone else stays on Denmark.
- Usage logged in `node_usage`; admin via `admin/api.php?action=node-usage` + `node-allowlist-add/remove`.

## 4. ⚠️ Hosting decision needed before enabling `api.setalink.no/v1`
`api.setalink.no` currently resolves to **65.109.183.7 (Helsinki, the test VPN node)**. But `/v1` (`v1.php`) needs the control-plane **SQLite DB** (`data/analytics.db`, allowlist, bootstrap settings), which lives on the **Copenhagen control box `5.249.252.221`** (same box as `setalink.no`). So:
- **Recommended:** repoint `api.setalink.no A → 5.249.252.221` (control box), add an additive `:4430` vhost routing `/v1/` → `v1.php` (forward `Authorization`), issue LE cert. Helsinki keeps `fi.setalink.no` for VPN only.
- Do **not** host the control API on the test VPN node (it would couple user discovery to a box we may decommission).

This is a DNS change you control; no assumptions made here — just flagging that the current `api.setalink.no → Helsinki` record must move (or a different control-plane host be chosen) before `/v1` works.

## 7. Rollback / safety
- Client changes are inert until a v0.9.34 build ships; current users untouched.
- If `api.setalink.no/v1` is later enabled and misbehaves: point its DNS away or disable the vhost → v0.9.34 clients fall back to the saved bootstrap (same graceful degradation as today). `DELETE FROM node_allowlist` revokes all test access.
- The staged `api.setalink.net` nginx vhost on the Copenhagen box has been **removed** (was inert).
